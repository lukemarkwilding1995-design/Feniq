# Field-limited learning dataset cycle - 21 September 2026

Branch: `feniq-phase1-platform`. Development and the fictional demonstration remain local; `main` and the private technical library are unchanged.

Migration `0010_learning_dataset` adds an append-only second decision for a reviewed outcome revision and exact prepared-payload hash. A company admin first chooses “Prepare for de-identification” on the current opted-in outcome. The app then derives a preview using a strict field allowlist. A separate admin decision can approve that exact preview for local company research or reject it. The decision and checksum are retained with an audit event. Corrections or consent withdrawal immediately remove a previously approved record from the active internal dataset, while decision history remains visible.

Prepared schema v1 includes only: controlled product category, controlled diagnostic module or “Unclassified,” diagnosis-match category, resolved/repeat-visit booleans, part/remake correctness category, 1–5 usefulness rating, verification definition revision, and four controlled verification answers. It excludes customer/site identity, job/company/engineer IDs, dates, locations, photos, measurements, technical-document content, free-text faults, diagnoses, repairs, notes and feedback. The source snapshot and outcome hashes must validate, and the structured verification definition must be supported. The prepared payload is field-limited, **not anonymous**: source linkage is retained in the company database, and rare combinations could still be identifiable.

API: `GET /api/learning/dataset-candidates`, `POST /api/learning/dataset-decisions`, `GET /api/learning/internal-dataset`, and paginated `GET /api/learning/dataset-history`. All require a company admin. The internal dataset response contains only currently eligible prepared payloads, without source IDs. The UI shows the exact preview, a separate approve/reject form, active count and retained decision history. No endpoint exports to a third party, retrains a model, or changes diagnostic rules.

Validation: 28 automated tests pass, including migration, role/tenant isolation, missing first review, preview checksum mismatch, immutable decision, forbidden free-text absence from the stored payload, current approval and automatic removal after opt-out. JavaScript syntax passes. The local demo database was migrated to 0010, and a second clearly fictional inspection (`DEMO-DATASET-01`) was prepared and approved through the visible browser; the admin page shows one active local record. Neither demo inspection nor private source files are committed.

Limits: the two decisions are separate steps but the same company admin may perform both. There is no privacy certification, aggregation threshold, external release, cross-company pooling, model-training approval, or evaluation pipeline. PostgreSQL DDL is supplied but not server-tested. Source linkage and the private record remain accessible to authorised company users; a privileged database rewrite could defeat hashes/triggers. Next: policy for two-person review, aggregation thresholds and revocation handling before any wider dataset use.
